# Localization (Arabic / English, RTL / LTR)

Phase 0 documents, accepted in direction on 2026-11-18, plus the Phase 1.1 dependency gate (library decided on 2026-11-20: `next-intl@4.15.1`, pinned exactly). **Phase 1.1 was accepted on 2026-11-20, Phase 1.2 (pure i18n core, 184 tests) and Phase 1.3 (language shell in the root layout, English only; 221 unit tests, 193 E2E), Phase 1.4 (client language plumbing, no UI: cookie code, `useLanguage()` hook, typed message keys; 291 unit tests, no Docker E2E), Phase 1.5 (lint guard: `eslint-plugin-i18next`, 514 existing literals as warnings, a strict baseline check in `npm run lint`; 319 unit tests, no Docker E2E) and Phase 1.6 (E2E language option and a temporary strings table, English only; 351 unit tests, Docker E2E 193 of 193) and Phase 1.7a (pure pseudo-locale generator, not wired; 458 unit tests at the time), **Phase 3** (English message extraction: 539 keys in 18 namespaces, lint baseline 514 to 0, 498 unit tests, Docker E2E 251 of 251) on 2026-11-21, and **Phase 1.7b** (the pseudo-locale in an E2E-only build, isolated from every normal build; 66 pseudo-locale tests, 512 unit tests, product suite 253 of 253) on 2026-11-22** (limitations: ARM64 on real hardware untested, Vercel itself untested, E2E run with a temporary copy of `stack.mjs`, known issue KI-1 (intermittent, not resolved), the open observations of plan step 1.3, and the future multi-language consistency risk of ADR-0001 decision 13); nothing else is implemented, nothing is committed or deployed yet, and the visible language behaviour is unchanged (English, `ltr`). Read in this order:

1. [ADR-0001: Localization architecture](ADR-0001-localization-architecture.md): `next-intl` without URL prefixes, language resolution, SSR and hydration, language vs formatting locale vs currency vs numbering, and the library decision.
2. [ADR-0002: Arabic font](ADR-0002-arabic-font.md): IBM Plex Sans Arabic vs Noto Sans Arabic, with measured sizes and licences (candidate; Phase 2 gate).
3. [Glossary, English to Arabic](GLOSSARY-AR-EN.md): the fixed terminology (needs native review before extraction).
4. [Arabic MVP and the plan for Phase 1](MVP-AND-PHASE-1-PLAN.md): scope, acceptance criteria, the phases and Phase 1 split into small changes.
5. [Phase 1.1: dependency and build compatibility gate](PHASE-1.1-DEPENDENCY-GATE.md): measured comparison of `next-intl` and `use-intl` (amd64, ARM64 under QEMU, SSR, native files, audit, size, timing) and what is still unproven; since the acceptance it also holds the results on the real project (section 12) and the known issue KI-1 (section 13).
